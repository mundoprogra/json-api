If your application keeps the Domain apart from the Infrastructure, the client query does not have to reach the Domain as an HTTP request or as an Eloquent builder. The package hands it over already validated in a plain object (ListCriteria), and a bridge applies it to Eloquent from your repository.

Nothing changes for whoever uses the macros. jsonApiFilter(), jsonApiSort(), jsonApiInclude() and jsonApiPaginate() keep working the same, and now they share the same code with the bridge. This page is for whoever wants to take the package into a layered architecture.

The flow

Every piece lives in its own layer, and only ListCriteria crosses inwards:

Controller (API)
  Allowed + $request->jsonApiQuery()->criteria()   ->  ListCriteria
                                                          |
Use case (Application)                                    v
  ListArticles::handle(ListCriteria)  ->  ArticleRepository (Domain interface)
                                                          |
Repository (Infrastructure)                               v
  EloquentArticleRepository  ->  ApplyCriteria  ->  Eloquent query  ->  entities
                                                          |
Controller (API)                                          v
  ArticleResource::collection(page of entities)  ->  JSON:API document

Nothing in the Domain imports a Laravel class, and nothing in the API knows about columns.

1. What the API allows: Allowed

Allowed is the API whitelist: what can be filtered, sorted and included, with API names and nothing else (no columns, no scopes, no Eloquent):

use MundoProgra\JsonApi\Query\Allowed;

$allowed = Allowed::make(
  filter: ['status', 'author', 'title', 'published'],
  sort: ['id', 'title', 'created_at'],
  include: ['author', 'tags', 'comments.author'],
  defaultSort: '-id',
);

Names are in snake_case, as in the macros. Allowing a path (comments.author) also allows its prefixes (comments). It is immutable and it is checked when built: a repeated or invalid name, a 'name' => 'column' pair or a default sort that is not in the sort list is a developer error (InvalidArgumentException), not a 400 for the client. Which column each name points to is decided later, in the repository.

2. The validated query: criteria()

The controller checks the query against Allowed and hands the result to the use case:

use Illuminate\Http\Request;
use MundoProgra\JsonApi\Query\Allowed;

class ArticleController {
  public function index(Request $request, ListArticles $listArticles) {
    $criteria = $request->jsonApiQuery()->criteria($this->allowed(), perPage: 20, maxPerPage: 100);

    return ArticleResource::collection($listArticles->handle($criteria));
  }

  private function allowed(): Allowed {
    return Allowed::make(
      filter: ['status', 'author', 'title', 'published'],
      sort: ['id', 'title', 'created_at'],
      include: ['author', 'tags', 'comments.author'],
      defaultSort: '-id',
    );
  }
}

The page size is decided just as with jsonApiPaginate() (client, argument, middleware options and config, capped by the maximum). ListCriteria carries nothing from Laravel, so it can live in the Application layer:

MethodWhat it returns
filters() / filter('status')The filters the client asked for, with their value as text (null if that filter was not asked for)
sort()The sort, already with the default if the client asked for none: a list of ['field' => 'title', 'descending' => true]
includes()The include paths (comments.author)
pageNumber(), pageSize(), offset()The page, its size and how many rows come before it

It can also be built by hand, to test a use case without HTTP:

use MundoProgra\JsonApi\Query\ListCriteria;

$criteria = new ListCriteria(
  pageSize: 10,
  pageNumber: 2,
  filters: ['status' => 'published'],
  sort: [['field' => 'id', 'descending' => true]],
  includes: ['author'],
);

When something is not allowed

Unlike the macros, which stop at the first problem, criteria() gathers everything the client asked for outside the list and answers it together in a single 400, in the order include, sort, filter, page. A filter is pointed at with the name the client wrote (filter[blockedBy]). The errors are those of Query parameters and Errors.

3. The Infrastructure repository: ApplyCriteria

The repository translates the API names to its model with a map and applies the criteria. The map is the same as in the macros: exact (equality; with commas, an IN), partial (LIKE %value%), scopes and, for the sort, sort:

use Illuminate\Pagination\LengthAwarePaginator;
use MundoProgra\JsonApi\Query\Eloquent\ApplyCriteria;
use MundoProgra\JsonApi\Query\ListCriteria;

class EloquentArticleRepository implements ArticleRepository {
  public function paginate(ListCriteria $criteria): LengthAwarePaginator {
    $query = ApplyCriteria::to(
      ArticleModel::query(),
      $criteria,
      exact: ['status', 'author' => 'author_id'],
      partial: ['title'],
      scopes: ['published'],
      sort: ['id', 'title', 'created_at'],
    );

    return ApplyCriteria::paginate($query, $criteria)
      ->through(fn(ArticleModel $row) => $this->toEntity($row));
  }
}
  • to() applies the filters, the sort and the includes, in that order, and returns the same query. It does not paginate: the page is asked for separately with paginate(), so the repository can also count or walk without it. Each step exists on its own: filters(), sort() and includes().
  • The sort adds the primary key at the end (if it is not there already) so the pages are stable, and a column two names point to is ordered only once.
  • The include paths are loaded as they are, as Eloquent relation names. If they are called something else in your model, do the with() yourself instead of using to().
  • It reads neither the request nor the configuration: everything comes in its arguments, so it is tested with a database and a hand-built ListCriteria.
  • A name the criteria carries and the map does not know is a LogicException, not an ignored filter: Allowed and the repository do not match, and it is better to see it in the first test than to return too many rows without a word. The same name in two lists is an InvalidArgumentException.

If your Domain must not know Laravel's paginator, have the repository return your own page type and build the LengthAwarePaginator in the controller with new LengthAwarePaginator($items, $total, $perPage, $page). The pagination links and meta come out the same with plain objects as with models.

4. Resources from entities

A ResourceObject does not require an Eloquent model. With an entity or a DTO, the resource declares type() and id() (there is no table or route key to work them out from) and decides on its own whether a relationship is present, because a plain object has no whenLoaded():

class ArticleResource extends ResourceObject {
  public function type(): string {
    return 'articles';
  }

  public function id(): string {
    return (string) $this->resource->id;
  }

  protected function jsonApiRoute(): ?string {
    return 'articles.show';
  }

  protected function jsonApiAttributes(Request $request): array {
    return ['title' => $this->resource->title];
  }

  protected function jsonApiRelationships(Request $request): array {
    return [
      'author' => $this->when(
        property_exists($this->resource, 'author'),
        fn() => Relationship::one($this->resource->author, AuthorResource::class),
      ),
    ];
  }
}

Relationship::one() and Relationship::many() accept any object: the resource class you pass them is the one that understands it. A relationship to a null object comes out as data: null. fields[type] is applied by the resource itself, which is why it is not part of ListCriteria.

The 201 response

With a model that was just created the package answers 201 by itself. A plain object has no wasRecentlyCreated, so the create endpoint asks for it with asCreated():

public function store(Request $request, CreateArticle $createArticle) {
  $article = $createArticle->handle(/* ... */);

  return ArticleResource::make($article)->asCreated();
}

It answers 201 with a Location header equal to the links.self of the resource. Without asCreated(), a plain object answers 200; with it, it wins even over a model that was not just created.

What it does not cover

  • Filter values are always text: turning them into a number, a date or an enum is up to the use case or the repository.
  • ListCriteria carries the filter, the sort, the includes and the page; it does not carry fields, which the resource applies when it builds the response.
