The package follows semantic versioning: MAJOR.MINOR.PATCH. This page explains what each number means, which Laravel and PHP versions it is tested with, and until when it receives fixes.

What a version is

A version is a git tag (for example v0.1.0) that Packagist publishes. A single version of the package covers several Laravel versions (today 10 to 13): there is no line of versions per Laravel.

Where it is today

Today the package is in 0.x: the API is complete and tested, but it is being validated in real use. In 0.x the API may change between minor versions. With ^0.1, Composer installs only 0.1.x; a 0.2.0 does not come in on its own.

The rules

  1. A new Laravel or PHP does not force a major version change: the major number goes up only if the API breaks or support is dropped.
  2. Dropping support for a Laravel or PHP version is a major change (while the package is in 0.x a minor one is enough).
  3. Laravel 10 and 11 are kept for the whole 1.x line and are dropped together in 2.0.0.
  4. The effective PHP range is the intersection of php: ^8.1 with what each Laravel requires; Composer resolves it.
  5. Before publishing a version, the full test matrix, the static analysis and the code style are run, and the versions table and the CHANGELOG are updated.

Security fixes

Only the latest published version receives security fixes (today, the most recent 0.x). How to report a vulnerability is in the security policy.
