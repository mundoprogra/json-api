Proyecto

Versionado y soporte

El paquete sigue el versionado semántico: MAYOR.MENOR.PARCHE. Esta página explica qué significa cada número, con qué versiones de Laravel y de PHP se prueba, y hasta cuándo recibe correcciones.

Qué es una versión

Una versión es una etiqueta de git (por ejemplo v0.1.0) que Packagist publica. Una sola versión del paquete cubre varias versiones de Laravel (hoy de la 10 a la 13): no hay una línea de versiones por cada Laravel.

Dónde está hoy

Hoy el paquete está en 0.x: la API está completa y probada, pero se está validando en uso real. En 0.x la API puede cambiar entre versiones menores. Con ^0.1, Composer instala solo 0.1.x; una 0.2.0 no entra sola.

La secuencia prevista

VersiónQué significaLaravel
0.1.0 y siguientesEn validación; la API puede cambiar entre versiones menores10–13
1.0.0API estable: las macros, las claves de config/json-api.php, los alias de middleware, los códigos de error, las claves de lang/ y los nombres de clases y de trait10–13
1.1.0, 1.2.0…Suman un Laravel o un PHP nuevo y funciones nuevas, sin romper nada10–14, 10–15…
1.0.1…Correcciones, incluidas las incompatibilidades internas con un Laravel o un PHP nuevoigual
2.0.0Retira Laravel 10 y 11 (que ya no reciben soporte) y puede cambiar la API pública; la línea 1.x queda un tiempo solo con correcciones críticas o de seguridad12 en adelante

Las reglas

  1. Un Laravel o un PHP nuevo no obliga a un cambio de versión mayor: el número mayor sube solo si se rompe la API o se retira soporte.
  2. Retirar el soporte de un Laravel o de un PHP es un cambio mayor (mientras el paquete esté en 0.x basta uno menor).
  3. Laravel 10 y 11 se conservan durante toda la línea 1.x y se retiran juntos en 2.0.0.
  4. El rango de PHP efectivo es la intersección de php: ^8.1 con lo que exige cada Laravel; Composer lo resuelve.
  5. Antes de publicar una versión se corre la matriz completa de pruebas, el análisis estático y el estilo, y se actualizan la tabla de versiones y el CHANGELOG.

Con qué se prueba

La integración continua corre las pruebas con cada una de estas combinaciones, con las dependencias en su última versión y en su versión mínima. Las combinaciones que no aparecen no se prueban:

LaravelPHP
108.1, 8.2, 8.3
118.2, 8.3, 8.4, 8.5
128.2, 8.3, 8.4, 8.5
138.3, 8.4, 8.5

Correcciones de seguridad

Solo la última versión publicada recibe correcciones de seguridad (hoy, la 0.x más reciente). Cómo reportar una vulnerabilidad está en la política de seguridad.
