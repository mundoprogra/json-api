Uso con Clean Architecture

Si tu aplicación separa el Dominio de la Infraestructura, la consulta del cliente no tiene por qué llegar hasta el Dominio como una petición HTTP ni como un constructor de Eloquent. El paquete la entrega ya validada en un objeto simple (ListCriteria), y un puente la aplica a Eloquent desde tu repositorio.

No cambia nada para quien usa las macros. jsonApiFilter(), jsonApiSort(), jsonApiInclude() y jsonApiPaginate() siguen funcionando igual, y ahora comparten con el puente el mismo código. Esta página es para quien quiere llevar el paquete a una arquitectura por capas.

El flujo

Cada pieza vive en su capa, y solo ListCriteria cruza hacia adentro:

Controlador (API)
  Allowed + $request->jsonApiQuery()->criteria()   ->  ListCriteria
                                                          |
Caso de uso (Aplicación)                                  v
  ListArticles::handle(ListCriteria)  ->  ArticleRepository (interfaz del Dominio)
                                                          |
Repositorio (Infraestructura)                             v
  EloquentArticleRepository  ->  ApplyCriteria  ->  consulta de Eloquent  ->  entidades
                                                          |
Controlador (API)                                         v
  ArticleResource::collection(página de entidades)  ->  documento JSON:API

Nada del Dominio importa una clase de Laravel, y nada de la API sabe de columnas.

1. Lo que permite la API: Allowed

Allowed es la lista blanca de la API: qué se puede filtrar, ordenar e incluir, con nombres de la API y nada más (ni columnas, ni scopes, ni Eloquent):

use MundoProgra\JsonApi\Query\Allowed;

$allowed = Allowed::make(
  filter: ['status', 'author', 'title', 'published'],
  sort: ['id', 'title', 'created_at'],
  include: ['author', 'tags', 'comments.author'],
  defaultSort: '-id',
);

Los nombres van en snake_case, como en las macros. Permitir una ruta (comments.author) permite también sus prefijos (comments). Es inmutable y se revisa al construirlo: un nombre repetido o no válido, una pareja 'nombre' => 'columna' o un orden por defecto que no está en la lista de orden es un error del programador (InvalidArgumentException), no un 400 para el cliente. A qué columna apunta cada nombre se decide después, en el repositorio.

2. La consulta validada: criteria()

El controlador revisa la consulta contra Allowed y entrega el resultado al caso de uso:

use Illuminate\Http\Request;
use MundoProgra\JsonApi\Query\Allowed;

class ArticleController {
  public function index(Request $request, ListArticles $listArticles) {
    $criteria = $request->jsonApiQuery()->criteria($this->allowed(), perPage: 20, maxPerPage: 100);

    return ArticleResource::collection($listArticles->handle($criteria));
  }

  private function allowed(): Allowed {
    return Allowed::make(
      filter: ['status', 'author', 'title', 'published'],
      sort: ['id', 'title', 'created_at'],
      include: ['author', 'tags', 'comments.author'],
      defaultSort: '-id',
    );
  }
}

El tamaño de página se decide igual que con jsonApiPaginate() (cliente, argumento, opciones del middleware y configuración, acotado por el máximo). ListCriteria no trae nada de Laravel, así que puede vivir en la capa de Aplicación:

MétodoQué devuelve
filters() / filter('status')Los filtros que pidió el cliente, con su valor como texto (null si no pidió ese filtro)
sort()El orden, ya con el default si el cliente no pidió ninguno: una lista de ['field' => 'title', 'descending' => true]
includes()Las rutas de include (comments.author)
pageNumber(), pageSize(), offset()La página, su tamaño y cuántas filas quedan antes de ella

También se puede armar a mano, para probar un caso de uso sin HTTP:

use MundoProgra\JsonApi\Query\ListCriteria;

$criteria = new ListCriteria(
  pageSize: 10,
  pageNumber: 2,
  filters: ['status' => 'published'],
  sort: [['field' => 'id', 'descending' => true]],
  includes: ['author'],
);

Cuando algo no está permitido

A diferencia de las macros, que se detienen en el primer problema, criteria() reúne todo lo que el cliente pidió fuera de la lista y lo responde junto en un solo 400, en el orden include, sort, filter, page. Un filtro se señala con el nombre que escribió el cliente (filter[blockedBy]). Los errores son los de Parámetros de consulta y Errores.

3. El repositorio de Infraestructura: ApplyCriteria

El repositorio traduce los nombres de la API a su modelo con un mapa y aplica el criterio. El mapa es el mismo de las macros: exact (igualdad; con comas, un IN), partial (LIKE %valor%), scopes y, para el orden, sort:

use Illuminate\Pagination\LengthAwarePaginator;
use MundoProgra\JsonApi\Query\Eloquent\ApplyCriteria;
use MundoProgra\JsonApi\Query\ListCriteria;

class EloquentArticleRepository implements ArticleRepository {
  public function paginate(ListCriteria $criteria): LengthAwarePaginator {
    $query = ApplyCriteria::to(
      ArticleModel::query(),
      $criteria,
      exact: ['status', 'author' => 'author_id'],
      partial: ['title'],
      scopes: ['published'],
      sort: ['id', 'title', 'created_at'],
    );

    return ApplyCriteria::paginate($query, $criteria)
      ->through(fn(ArticleModel $row) => $this->toEntity($row));
  }
}
  • to() aplica los filtros, el orden y las inclusiones, en ese orden, y devuelve la misma consulta. No pagina: la página se pide aparte con paginate(), para que el repositorio pueda también contar o recorrer sin ella. Cada paso existe por separado: filters(), sort() e includes().
  • El orden agrega la clave primaria al final (si no está ya) para que las páginas sean estables, y una columna a la que apuntan dos nombres se ordena una sola vez.
  • Las rutas de include se cargan tal cual como nombres de relación de Eloquent. Si en tu modelo se llaman distinto, haz tú el with() en vez de usar to().
  • No lee la petición ni la configuración: todo viene en sus argumentos, así que se prueba con una base de datos y un ListCriteria armado a mano.
  • Un nombre que el criterio trae y el mapa no conoce es un LogicException, no un filtro ignorado: Allowed y el repositorio no coinciden, y es mejor verlo en la primera prueba que devolver filas de más sin avisar. Un mismo nombre en dos listas es un InvalidArgumentException.

Si tu Dominio no debe conocer el paginador de Laravel, haz que el repositorio devuelva tu propio tipo de página y arma el LengthAwarePaginator en el controlador con new LengthAwarePaginator($items, $total, $perPage, $page). Los links y el meta de paginación salen igual con objetos simples que con modelos.

4. Recursos desde entidades

Un ResourceObject no exige un modelo de Eloquent. Con una entidad o un DTO, el recurso declara type() e id() (no hay tabla ni clave de ruta de dónde sacarlos) y decide por su cuenta si una relación está presente, porque un objeto simple no tiene whenLoaded():

class ArticleResource extends ResourceObject {
  public function type(): string {
    return 'articles';
  }

  public function id(): string {
    return (string) $this->resource->id;
  }

  protected function jsonApiRoute(): ?string {
    return 'articles.show';
  }

  protected function jsonApiAttributes(Request $request): array {
    return ['title' => $this->resource->title];
  }

  protected function jsonApiRelationships(Request $request): array {
    return [
      'author' => $this->when(
        property_exists($this->resource, 'author'),
        fn() => Relationship::one($this->resource->author, AuthorResource::class),
      ),
    ];
  }
}

Relationship::one() y Relationship::many() aceptan cualquier objeto: la clase de recurso que les pasas es la que lo entiende. Una relación a un objeto null sale como data: null. fields[tipo] lo aplica el propio recurso, por eso no forma parte de ListCriteria.

La respuesta 201

Con un modelo recién creado el paquete responde 201 solo. Un objeto simple no tiene wasRecentlyCreated, así que el alta lo pide con asCreated():

public function store(Request $request, CreateArticle $createArticle) {
  $article = $createArticle->handle(/* ... */);

  return ArticleResource::make($article)->asCreated();
}

Responde 201 con la cabecera Location igual al links.self del recurso. Sin asCreated(), un objeto simple responde 200; con él, gana incluso sobre un modelo que no es recién creado.

Lo que no cubre

  • Los valores de los filtros son siempre texto: convertirlos a número, fecha o enumeración lo hace el caso de uso o el repositorio.
  • ListCriteria lleva el filtro, el orden, las inclusiones y la página; no lleva fields, que aplica el recurso al armar la respuesta.
